REVIEW ROUND D — two more real P0s fixed (before any smoke):
  A. Missing acquire: pkvm_cov_end() now count = smp_load_acquire(&ring->count)
     (was plain READ_ONCE) to pair with the EL2 callback's smp_store_release(&count),
     so pcs[] published before count are guaranteed visible under the ARM model.
  B. Teardown lifecycle: host ring pointer is now __rcu. disable() = disarm +
     rcu_assign_pointer(NULL) -> synchronize_rcu() (wait for in-flight begin/end
     preempt-off sections) -> __pkvm_cov_setup(0) on owner CPU CHECKED (IPI result
     AND hyp return) -> only then unshare/free. If unconfirmed (owner offline / IPI
     fail / hyp error): keep disabled and LEAK the page (never free one EL2 may map).
     begin() returns the ring (rcu_dereference_check), end(ring) takes it — no second
     lockless global read; pointer valid through end() because the free waits on the
     grace period. (Assumes non-RT: mmu_lock disables preemption = RCU read side.)
  Also: stale doc line "#23 hook NOT wired" removed (contradicted "wired").

ATTRIBUTION + REQUIRED SERIALIZATION (single-page/single-CPU MVP)
----------------------------------------------------------------
Attribution is by `current`: the #23 fault runs synchronously in the vCPU thread's
KVM_RUN syscall, so kcov_add_pcs() lands PCs in exactly that task's KCOV area. This
is correct per-call irrespective of concurrency. But the ring is ONE page on ONE
CPU, so KVM_RUNs on other CPUs collect nothing (owner guard). A physical DUT is NOT
serial by default; for this MVP force: procs=1, Threaded=false, Collide=false,
executor pinned to owner CPU. syz-execprog can (`-procs=1 -threaded=0 -collide=0`);
syz-manager has NO knob to disable its default Threaded/Collide -> a Stage-2-only
exec mode must be added before a manager campaign. Per-online-CPU rings later
restore controlled concurrency (attribute by the syscall returning to EL1 on that
CPU). load.go:101 / fuzzer.go:486 / manager.go:1184.
