REPRODUCE (from recorded inputs only)
-------------------------------------
  git -C <tree> checkout da966ce9a047bedffb02e0bdc87f3ccb5fb3f9d9
  git -C <tree> apply /path/to/stage2-el2-kcov.patch
  cp /path/to/stage2.config <tree>/.config
  make -C <tree> ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- olddefconfig
  make -C <tree> ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- -j$(nproc) Image modules
  # then verify sha256(Image/vmlinux/System.map) and the vmlinux Build ID below.
  # (olddefconfig must leave CONFIG_PKVM_EL2_COV=y: grep it in <tree>/.config.)

REPRODUCIBILITY SCOPE (be precise)
----------------------------------
The REPRODUCE recipe gives FUNCTIONAL reproducibility: same source + same .config ->
a functionally identical CONFIG_PKVM_EL2_COV=y kernel. It does NOT guarantee a
bit-for-bit identical SHA-256 on another machine/time, because the build embeds a
build identity that is not yet pinned: KBUILD_BUILD_TIMESTAMP, KBUILD_BUILD_VERSION
(e.g. "#25 SMP Thu Jul 23 11:01:29 +08 2026"), KBUILD_BUILD_USER/HOST, and the exact
toolchain. So the recorded hashes VERIFY the frozen binary is unchanged; they are not
a promise that a rebuild reproduces the same hash.
Toolchain used for the frozen build:
  C:    aarch64-linux-gnu-gcc (Ubuntu 15.2.0-16ubuntu1) 15.2.0 ; GNU ld 2.46
  Rust: nightly-2025-05-05  (rustc 1.88.0-nightly 13e879094 2025-05-04)
FOR THE SMOKE: deploy THIS frozen Image + THIS vmlinux (hashes above); do NOT rebuild
just to run the smoke. If true bit-for-bit reproducibility is ever required, pin the
KBUILD_BUILD_* vars and the toolchain identity, then rebuild.
