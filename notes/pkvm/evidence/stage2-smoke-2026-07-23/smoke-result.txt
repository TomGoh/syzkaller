Stage-2 EL2-KCOV — single-CPU manual closed-loop smoke: PASS (N90, 2026-07-23)
==============================================================================
The first real-hardware proof that EL2 (Rust pKVM hyp) coverage reaches syzkaller
and symbolizes to Rust source. Scope: the loop only; NOT a manager campaign, and
coverage is TRUNCATED (see OVERFLOW below).

METHOD (on N90, non-default GRUB entry '6.6.30+ pKVM EL2-cov smoke'):
  # kprobe on pkvm_mem_abort (fault ipa = *x1, ret = $retval)
  # all pinned to CPU 0; ring enabled via debugfs on CPU 0:
  sudo taskset -c 0 sh -c 'echo 1 > /sys/kernel/debug/kvm/pkvm_cov/enable;
    ./syz-execprog -executor=./syz-executor -procs=1 -threaded=0 -cover=1 \
      -slowdown=10 -coverfile=/tmp/pkvm-el2.raw arm64-syz_kvm_run_fw_fault;
    echo 0 > /sys/kernel/debug/kvm/pkvm_cov/enable'
  Note: this kernel has CONFIG_KCOV_ENABLE_COMPARISONS=n, so the executor's
  comparison-coverage probe returns errno 524 (ENOTSUPP) and it falls back to
  trace-pc (comps=0 cover=1) -- which is exactly what the EL2 drain needs.

OVERFLOW (must not be called complete coverage):
  4x "pkvm_cov: ring overflow (count=511) -- coverage truncated". A pvmfw boot
  generates >511 instrumented EL2 basic-block hits per #23 fault, so each drain
  captured only the first 511. The loop is PROVEN; the coverage is a SAMPLE, not
  the full EL2 trace. Follow-up before any campaign: larger ring and/or more
  frequent drain, plus the executor CPU-pin + Threaded/Collide-off Stage-2 exec
  mode (this smoke forced serialization by hand with taskset + -procs=1 -threaded=0).
